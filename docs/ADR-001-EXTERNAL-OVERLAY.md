# ADR-001：使用外部透明覆盖层模拟 QQ 内嵌插件

- 状态：已接受
- 日期：2026-09-22

## 背景

项目需要在 Windows QQ 的对应聊天消息附近显示 Jev 判断卡，视觉效果应接近“分析结果直接出现在消息下面”。

实现方式包括：

1. 向 QQ 进程注入代码或 Hook 内部控件。
2. 修改 QQ 文件或运行时界面树。
3. 使用独立进程创建透明覆盖层，并根据 QQ 窗口和消息位置绘制卡片。

## 决定

采用第 3 种方式：

```text
QQ.exe
  │ 只读窗口位置、可访问界面信息或可见截图
  ▼
QQJevHud.exe
  │ 在独立透明窗口中绘制注释卡
  ▼
视觉上贴近 QQ 消息，但不进入 QQ 进程
```

## 原因

- 不修改 QQ 本体，降低账号、稳定性和安全风险。
- QQ 崩溃时不会直接带崩分析程序，反之亦然。
- 可以独立暂停、退出、升级和调试。
- 模型密钥与网络请求全部留在伴生程序中。
- QQ 版本变化时，通常只需更新窗口识别和消息定位规则。
- 可以实现接近参考图的逐消息判断卡效果。

## 视觉等价目标

用户应感受到卡片属于对应消息：

- 卡片与消息气泡保持固定的视觉关系。
- QQ 窗口移动、缩放和滚动时，卡片同步移动。
- QQ 最小化、失焦或切换联系人时，旧卡片及时隐藏。
- 卡片不抢占 QQ 输入焦点。
- 颜色、间距和字体尽量融入 QQ 界面。

## 无法完全等价的部分

独立覆盖层不能改变 QQ 原生布局，因此不能真正把后续消息向下推开。处理顺序为：

1. 优先放在消息下方现有空白区域。
2. 空间不足时放在消息侧边。
3. 发生遮挡时进入固定侧边轨道。
4. 极端拥挤时折叠为小型 Jev 标记。

任何时候都不得覆盖消息正文、输入框、未读标记和关键 QQ 操作。

## 明确拒绝

- DLL 注入
- API Hook
- 内存扫描或修改
- 修改 QQ 安装文件
- 读取 QQ 聊天数据库
- 模拟用户自动发送消息

## 实施影响

- 使用 .NET 8 + WPF 创建无边框、透明、置顶且不激活的覆盖窗口。
- 使用 Win32 API 跟踪 QQ 主窗口位置、可见性和 DPI。
- 当前 QQ 9.9.19 的 UI Automation 不能读取正文，因此首版以可见区域截图和本地 OCR 为主。
- UI Automation 仅保留为未来 QQ 版本可用时的辅助锚点来源。
- 使用锚点管理器维护“消息指纹 → 屏幕坐标 → 判断卡”的关系。
- 使用碰撞检测选择消息下方、侧边轨道或折叠布局。

## 第一项技术验证

不连接真实 QQ，也不调用模型。先构造模拟聊天画面，验证：

1. 三张注释卡分别锚定三条消息。
2. 模拟滚动时卡片保持同步。
3. 卡片发生碰撞时自动转移到侧边轨道。
4. 覆盖窗口始终不抢输入焦点。
5. 暂停或切换会话时立即清空卡片。
