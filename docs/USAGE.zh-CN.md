# QQ Jev HUD 使用说明

面向使用者的完整操作手册。涵盖安装、配置、日常使用、设置详解和排查。

> 一句话原理：它**只读**你的 QQ 聊天画面 → 本地 OCR 认字 → 把「对方这条消息」发给判断服务 → 在消息旁浮出一张卡片，告诉你**对方想表达什么**，并按你选的话术**写出几条候选回复**。**发送永远由你点。**

## 1. 安装

**前置条件**：Windows 10/11、Python 3.12（x64）。.NET 8 SDK 若缺失，安装脚本会自动装上。

```powershell
git clone https://github.com/Evan26Ma/qq-jev-hud.git
cd qq-jev-hud
.\setup.ps1
```

`setup.ps1` 会做三件事：装 .NET 8 SDK（缺则装）、建项目专用 Python 环境 `.venv`、装本地 PaddleOCR。首次约需 5–15 分钟（要下模型）。

装完可选建桌面快捷方式：

```powershell
.\create-shortcut.ps1
```

## 2. 配置 API Key

两种服务，按需要配：

| 服务 | 作用 | 是否必需 |
| --- | --- | --- |
| **TypeSafe Jev** | 判断层：分析意图、情绪、风险、怎么回 | 想用真实判断就要 |
| **OpenAI 兼容 LLM** | 生成层：按话术写出候选回复 | 想要候选回复就要 |

两者都**不必需**——不配任何 Key 时程序以**离线 Mock 模式**运行（本地假数据），可以完整走一遍流程看效果。

> **Key 只存在 Windows 凭据管理器**，不会写进设置文件、源码、日志或 Git。卸载/清理时用 `cmdkey /delete:QQJevHud.TypeSafe.ApiKey`。

### 2.1 用界面配置（推荐）

启动后托盘图标右键 → **设置…**：

1. **决策服务** 选「Jev（TypeSafe）」→ 粘贴 Jev API Key → 点 **保存 Key**
2. 点 **验证**，应显示「可用 ✓（已返回真实判断）」
3. 要候选回复的话，选「OpenAI 兼容 LLM」，填 **Base URL** / **模型** / **API Key** → 保存并验证

### 2.2 用命令行配置

```powershell
# Jev
echo "<你的 TypeSafe API Key>" | .\src\QQJevHud\bin\Debug\net8.0-windows10.0.19041.0\QQJevHud.exe --set-typesafe-key

# OpenAI 兼容
echo "<你的 LLM API Key>" | .\src\QQJevHud\bin\Debug\net8.0-windows10.0.19041.0\QQJevHud.exe --set-openai-key
```

或用系统自带命令：

```powershell
cmdkey /generic:QQJevHud.TypeSafe.ApiKey /user:QQJevHud /pass:<你的 Key>
```

### 2.3 OpenAI 兼容服务怎么填

程序走标准的 `/chat/completions`，任何兼容服务都行：

| 服务 | Base URL | 模型示例 |
| --- | --- | --- |
| OpenAI | `https://api.openai.com/v1` | `gpt-4o-mini` |
| DeepSeek | `https://api.deepseek.com/v1` | `deepseek-chat` |
| Ollama（本地） | `http://localhost:11434/v1` | `qwen2.5:14b` |
| vLLM / 其他 | 你的服务地址 + `/v1` | 你的模型名 |

> Ollama 等本地服务不校验 Key，随便填一个非空值即可。

## 3. 启动

双击桌面 **QQ Jev HUD** 快捷方式，或：

```powershell
.\start.cmd
```

程序是**托盘程序**，没有主窗口。启动后托盘出现图标，并自动开始分析。

**关键前提**：QQ 必须在前台，卡片才会显示。程序只在前台是 QQ 时画卡，切到别的应用时自动隐藏——这是为了不遮挡你正在用的其他窗口。

### 常用启动参数

```powershell
$exe = ".\src\QQJevHud\bin\Debug\net8.0-windows10.0.19041.0\QQJevHud.exe"

& $exe --preview-card      # 用示例数据渲染一张判断卡，不需要 QQ
& $exe --preview-replies   # 用示例数据显示候选回复面板，不需要 QQ
& $exe --open-settings     # 启动并直接打开设置窗口
& $exe --verify-typesafe   # 检查 Jev Key 是否可用（退出码 0=可用）
```

## 4. 主界面

启动后会打开**主界面**（托盘右键 → 打开主界面）：

- **顶部**：一句话说明这个工具干什么，加实时状态（正在等待新消息 / 已暂停）
- **开始使用**：4 步检查清单，每步自带 ✓ 和「去配置 / 开始」按钮
  1. 配置判断服务（Jev）—— 未配置时给出按钮直达设置
  2. 配置候选回复（可选）
  3. 打开 QQ 聊天窗口 —— 自动检测 QQ 是否在运行
  4. 开始分析
- **它能做什么**：五个功能一句话说明
- **先看看效果**：两个按钮，用示例数据渲染判断卡 / 选择面板（**不需要 QQ、不联网**）

关闭主界面不会退出程序，它继续在托盘运行。

## 5. 日常使用

1. 打开 QQ，进入想观察的聊天窗口
2. 托盘右键 → **自动分析已开启**（或在主界面点「开始分析」）
3. 程序先把**当前可见消息当作基线**——不会为旧消息补卡
4. 等**新的左侧（对方）消息**进来：约 1–3 秒后浮出判断卡，同时弹出**选择面板**

### 托盘菜单

| 菜单项 | 作用 |
| --- | --- |
| 打开主界面 | 功能引导 + 配置检查 |
| 自动分析已开启 | 开始 / 继续分析 |
| 暂停自动分析 | 停止读取画面，清空内存中的卡片 |
| 重新校准聊天区域 | 手动框选消息区域（默认自动，位置不准时用） |
| 怎么回… | 打开选择面板 |
| 设置… | 打开设置 |
| 退出 | 完全退出程序 |

### 快捷键

`Ctrl + Alt + J` —— 暂停 / 恢复（全局生效，不必切回 QQ）

### 它会自动做的事

- **换会话自动重置**：切换联系人时清空旧会话状态，不会把上一个聊天的内容混进来
- **只认新消息**：同一条消息只分析一次，不会重复弹卡
- **画面稳定才识别**：等 QQ 画面稳定约 1 秒再 OCR，避免消息还在加载时误读

## 6. 看懂判断卡

卡片浮在 QQ 聊天窗口上，鼠标穿透（不挡点击、不抢焦点）。从下往上读：

```
┌─────────────────────────────────────────┐
│ Jev · 对方真实意图                       │  ← 卡片主题
│ 零：我昨天买的M7五级弹，4400一发…        │  ← ★ 引用：是谁说了什么
│ 她此刻最希望你怎样回应？                  │  ← 这次要回答的问题
│ ★ 真实意图                               │  ← ★ = 最该先看的判断
│   自然分享        54% ███████████        │
│   表达情绪        28% ██████             │
│ ★ 怎么回                                 │
│   轻松接话        67% █████████████      │
│   先问清楚        18% ████               │
│ 潜台词                                   │
│   含蓄表达不满    42% █████████          │
│   无明显潜台词    33% ███████            │
│ 情绪状态                                 │
│   平静            38% ████████           │
│   开心            28% ██████             │
│ 建议：认真回应重点，不要立…   低风险 · 2/10│  ← 建议 + 风险等级
└─────────────────────────────────────────┘
```

### 引用行（`零：我昨天买的M7…`）

**这是解决"群聊刷太快、卡片和消息对不上"的关键。** 卡片会引用它正在判断的那条消息，群聊时还带上发送者昵称。即使对话往下滚了，你也能凭这行认出卡片对应哪句话。

- 群聊：显示「发送者：消息内容」
- 单聊：显示「对方名字：消息内容」
- 超过 52 字自动截断并加省略号

### ★ 标记

带 ★ 的是**两个头条判断**：`真实意图`（对方想干嘛）和 `怎么回`（你该怎么接）。先看这两个通常就够了。

### 判断维度

| 维度 | 含义 |
| --- | --- |
| **★ 真实意图** | 对方最主要的沟通意图（希望具体回应 / 确认被在意 / 表达情绪 / 自然分享 / 寻求帮助 / 提出请求） |
| **★ 怎么回** | 最适合的回应方式（认真回应重点 / 先安抚情绪 / 给具体方案 / 轻松接话 / 先问清楚 / 设置边界） |
| 潜台词 | 字面之外有没有没直说的意思（试探在意程度 / 含蓄表达不满 / 暗示某个期待 / 无明显潜台词） |
| 情绪状态 | 平静 / 开心 / 期待 / 失落 / 焦虑 / 生气 / 冷淡 |
| 语气亲疏 | 客气疏远 → 很亲密（5 档） |
| 对方期待 | 要具体回答 / 要情绪安抚 / 要陪伴聊天 / 要一个安排 / 没什么期待 |
| 关系状态 | 正常推进 / 气氛紧张 / 正在缓和 / 僵持 / 有点疏远 |

每个维度最多显示**概率最高的两项**，带概率条——蓝色是首选，灰色是次选。

### 风险等级

右下角的「低风险 · 2/10」是关系风险：**1–3 低风险**（正常交流）、**5–7 需要留意**（要认真回应）、**8–10 高风险**（可能升级矛盾）。

### 卡片位置

空间不够时程序会自动调整，依次尝试：**消息下方** → **消息旁边** → **右侧边栏** → 缩成一个小圆点标记（鼠标移上去显示提示）。所以卡片不一定贴着消息，**靠引用行对号**。

> 判断是**概率性猜测**，不是事实，更不是心理诊断。把它当参考，别当结论。

## 7. 卡片里选回复

回复**长在卡片里**，不再单开窗口。判断卡默认收起，底部有一行 **「怎么回 ▾」**，点一下就地展开 4 个候选；再点 **「收起 ▴」** 收回去。

```
┌──────────────────────────────────────────┐
│ Jev · 对方真实意图                        │
│ 零：我昨天买的M7五级弹，4400一发…          │  ← 谁的哪句话
│ ★ 真实意图  自然分享 54%  表达情绪 28%      │
│ ★ 怎么回    轻松接话 67%  先问清楚 18%      │
│ 建议 轻松接话，别把话题聊死      低风险 2/10 │
│ ────────────────────────────────────────  │
│ 怎么回 ▾                                  │  ← 点这里展开
└──────────────────────────────────────────┘
                    ↓ 点击后
┌──────────────────────────────────────────┐
│ …（上面不变）                              │
│ 收起 ▴                                    │
│ ① 理科直男                                 │
│   确实贵，你是想囤还是自己用？              │
│   → 满意、顺利接住 58%  低风险             │  ← Jev 预测的结果
│ ② 阴阳怪气  → 被安抚、情绪缓和 62%  低风险   │
│ ③ 高情商话术 …                            │
│ ④ 自然接话  → 觉得被敷衍 41%  需要留意      │
└──────────────────────────────────────────┘
```

> 生成候选时底部会显示「正在想怎么回…」，好了自动变成「怎么回 ▾」。

### 每个选项都带"可能出现的结果"

这是和普通 AI 回复助手最大的不同：不是给你一堆文本让你猜哪条好，而是**每条都用 Jev 预测对方会怎么反应**，并标注风险：

| 预测的反应 | 含义 |
| --- | --- |
| 被安抚、情绪缓和 | 对方感到被理解，情绪明显变好 |
| 满意、顺利接住 | 对方接受了这个回复，对话顺畅推进 |
| 无明显变化 | 对方反应平淡，话题继续往下走 |
| 觉得被敷衍 | 对方觉得回答不够认真、在应付 |
| 可能更不满 | 对方可能因此更不高兴，甚至升级 |

一次请求并行评估全部候选，成本约等于一次判断。

### 排序规则

选项按**"更可能是好结果"**排序，而不是单纯按概率：先看反应好坏（能缓和/接住 > 平淡 > 敷衍/不满），再看风险高低，最后才看概率。所以「被安抚 55%」会排在「被敷衍 70%」前面。

### 点一下就填进去

**点击任一选项** → 内容填入 QQ 输入框，**不会自动发送**。卡片底部会提示结果；如果 QQ 没能聚焦，它会**自动退回复制**并提示你手动 `Ctrl+V`。

### 卡片跟着聊天窗口走

卡片是**钉在 QQ 窗口上**的：移动、缩放 QQ 窗口，卡片跟着一起走，不会留在原地。切换会话时卡片自动清空。

## 8. 联系人背景卡

给某个联系人/群写一份背景资料，判断和候选回复都会带上它——**这是提升准确率最有效的办法**。

1. 在项目根目录的 `notes/` 里建一个**以聊天标题命名**的文件，如 `notes/茶.md`、`notes/妈妈.md`
2. 写几行：

```markdown
# 茶

- 约定：周末下午是我们的时间，别安排别的事。
- 雷区：别提加班和体重。
- 近况：她这周在准备考试，压力比较大。
- 称呼：平时叫她「茶茶」。
```

3. **保存即生效**，不用重启

文件名要和 QQ 里显示的聊天标题一致。这个目录不会被提交到 Git，内容只在你机器上，且只在收到新消息时随当次请求发给你配置的服务商。

## 10. 设置详解

托盘右键 → **设置…**

### 状态 / 控制

实时状态 + 三个按钮：暂停分析 / 分析当前聊天 / 重新校准聊天区域。

### 决策服务

选判断引擎：**Jev（TypeSafe）** / **OpenAI 兼容 LLM** / **离线 Mock**。

- Jev：填 API Key
- OpenAI 兼容：填 Base URL、模型、API Key
- Mock：不用配，用本地确定性假数据（适合先看界面）

两者都有 **验证** 按钮，会发一条固定的测试消息探活（可能产生极少 API 费用）。

### 候选回复

自动生成开关、启用的话术、自定义话术。

### 卡片显示

- 显示意图判断（概率分布）
- 显示关系风险
- 显示回应建议
- 卡片透明度
- 同屏最多几张（1–8）

### 隐私

- **发送前脱敏敏感信息**：开启后，转账金额、账号、卡号、身份证、手机号、邮箱等在**出网前**先被替换成 `［已脱敏］`

### 通用

开机自启、查看诊断日志、全局快捷键说明。

## 11. 隐私说明

| 项目 | 说明 |
| --- | --- |
| 截图 | 只在内存中处理，**不落盘** |
| 聊天正文 | **不保存**，不写日志 |
| API Key | 只存 Windows 凭据管理器，不进设置文件/源码/日志/Git |
| 诊断日志 | 只记匿名状态码（如 `frame-settling`），不含任何聊天内容 |
| 发送范围 | 只在分析开启且收到新消息时，把**当前消息 + 最近可见上下文**发给所配置的服务商 |
| 脱敏 | 默认开启，敏感信息在出网前本地替换 |
| 剪贴板 | 只有你主动点「分析剪贴板」时才读取 |

程序**不会**做的事情：不注入 QQ、不 Hook、不修改 QQ、不读 QQ 数据库、不自动发送任何消息。

## 12. 排查

先看诊断日志：

```powershell
Get-Content "$env:LOCALAPPDATA\QQJevHud\runtime.log" -Tail 30
```

正常顺序：`qq-foreground` → `frame-settling` → `baseline-ready` → `waiting-for-incoming-message`

| 现象 | 原因与处理 |
| --- | --- |
| **看不到卡片** | QQ 必须在前台。点一下 QQ 聊天窗口让它真正到最前（被开始菜单、其他窗口挡着时程序会判定为"非前台"） |
| **卡片显示但位置飘** | 群聊刷太快或 QQ 滚动过。**看卡片顶部的引用行**对号；或托盘 → 重新校准聊天区域 |
| **一直"正在识别当前聊天…"** | 首次 OCR 要加载 Paddle 模型，约 15–30 秒，等它一下 |
| **显示 `ocr-unavailable`** | 重跑 `setup.ps1` 装 OCR 依赖；或检查 `.venv\Scripts\python.exe` 是否存在 |
| **卡片显示"Jev 请求失败: 422"** | 请求格式问题（本仓库已修）；若仍出现请提 issue |
| **卡片显示"Jev 请求失败: 400"** | 通常是 **API Key 里混入了多余字符**（换行/空格）。重新在设置里粘贴一次 Key |
| **卡片显示"Jev 未配置"** | Key 没配或没读到。设置 → 验证 |
| **没有候选回复** | 需要配 **OpenAI 兼容 LLM** 的 Key（判断走 Jev 也要单独配生成层） |
| **"填入 QQ" 没反应** | 会自动退回复制。手动切到 QQ 按 `Ctrl+V` |
| **QQ 切换会话后没反应** | 正常——换会话会重建基线，只分析之后的新消息 |

### 卡片导致 QQ 操作别扭？

卡片本身是**鼠标穿透**的，不会挡点击、不抢焦点。如果不放心，随时 `Ctrl+Alt+J` 暂停。

## 13. 常见问题

**Q：会把我聊天记录传出去吗？**
只传**当前这条消息 + 最近约 10 条可见上下文**，且只在收到新消息、分析开启时。不保存聊天记录，不落盘截图。

**Q：它会自动帮我回复吗？**
不会。「填入 QQ」只是把候选**粘贴**到输入框，**不按回车**。发不发、发什么，完全由你决定。

**Q：为什么只分析对方（左侧）的消息？**
设计如此。自己发的内容不重复生成卡片，避免刷屏。

**Q：能同时看多个聊天吗？**
不能。只分析**当前前台**的那个会话——切走即停，切回重建基线。

**Q：判断准吗？**
它是**概率性参考**，不是事实。中文语境、反讽、表情包都可能误判。配好[联系人背景卡](#7-联系人背景卡)能明显提升相关性。

**Q：必须用 Jev 吗？**
不必须。判断层也可以直接用 OpenAI 兼容 LLM（决策服务里切换）。不配 Key 时是离线 Mock 模式。

**Q：耗流量/花钱吗？**
一条消息一次判断请求。Jev 定价极低（约 $0.042/百万输入 token）；用 OpenAI 兼容服务则按你自己的服务商计费。

**Q：支持哪些 QQ 版本？**
Windows 桌面版 QQ（NT 版，Chromium 内核窗口）。其他版本界面结构不同，可能定位不到窗口。

```powershell
cmdkey /delete:QQJevHud.TypeSafe.ApiKey

```
